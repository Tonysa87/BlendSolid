# Milestone 1.5 — design decisions for the plan (controller, 2026-09-26)

Input for writing the milestone 1.5 implementation plan. Binding unless the plan finds them technically impossible
(then say so explicitly in the plan).

Sources: docs/spec.md (milestone 1.5 row), docs/research/2026-09-26-modeling-workflows.md (sections 4–7),
docs/decisions/0001–0004, docs/milestone-1-report.md, CLAUDE.md, and the milestone 1 code in blendsolid/.

## Scope
Tools 1–3 of the research: (1) parametric primitives from Shift+A, (2) the interactive Draw Solid tool on a face or
the grid, (3) booleans between parts with live cutters. Plus two small leftovers from milestone 1:
Recompute disabled (with an explanation) on untrusted parts; document Blender's `-Y` gap in ADR 0004.
Out of scope: selectors, provenance, fillet on clicked edges, push/pull, sketches, modal parameter edit with
letter keys, value HUD, Convert to BlendSolid, Apply Mesh, STEP import (all later).

## 1. Canonical script structure (new pure-Python module, e.g. blendsolid/script_model.py)
Scripts generated by tools follow one structure, which tools can edit safely with `ast`:

```python
# BlendSolid part. The numbers below are its parameters (millimetres).
box_1_length = 40.0
box_1_width = 30.0
box_1_height = 20.0
cut_1_length = 10.0
...

with BuildPart() as part:
    Box(box_1_length, box_1_width, box_1_height, align=Align.MIN)  # feature: box_1
    with Locations(Location((12.0, 8.0, 20.0), (0.0, 0.0, 0.0))):  # feature: cut_1
        Box(cut_1_length, ..., align=(Align.CENTER, Align.CENTER, Align.MAX), mode=Mode.SUBTRACT)

result = part.part
```

- Parameters are named `<feature>_<param>`; features carry a `# feature: <name>` marker on their first line.
- The module can: create a new canonical script from a first feature; append a feature (its parameters go at the end
  of the parameter block, its statement at the end of the `with BuildPart()` body); list features; tell whether a
  script is canonical. Tools refuse with a clear message (not an exception) on non-canonical scripts (e.g. the
  milestone 1 template or advanced users' hand edits) — except that the milestone 1 default template should be made
  canonical too.
- Unique feature names per part (`box_1`, `box_2`, `cut_1`...).
- Everything stays compatible with params.parse_params/set_param (milestone 1 panel keeps working).

## 2. Tool 1 — parametric primitives
- Shift+A → BlendSolid submenu: Box, Cylinder, Sphere, Cone, Torus, Wedge. Also listed in the BlendSolid N-panel.
- Operator per primitive with `bl_options = {'REGISTER', 'UNDO'}` and FloatProperty dimensions in millimetres
  (subtype DISTANCE is wrong here because scripts are mm: use plain floats with a "mm" hint), so Adjust Last
  Operation shows them; changing them rewrites the script (same operator re-executed by Blender's redo).
- New part at the 3D cursor, taking the cursor rotation (object transform, not script). Object named after the
  primitive ("Box", "Cylinder"...). New parts are trusted (ADR 0004 rule).
- Gizmos: Python `GizmoGroup` arrows on the main dimensions of the active part's primitives (box: length/width/height;
  cylinder: radius/height; ...), writing through the same path as the panel (part.set_param), so undo and the
  reconcile loop are unchanged. Gizmos must not hide Blender's transform gizmo (offset them) and must follow the
  object transform. Recompute while dragging relies on the existing per-part coalescing (latest value wins).
- Part scale stays 1 (scale belongs in the script): warn in the panel if the object is scaled.

## 3. Tool 2 — Draw Solid (WorkSpaceTool + modal operator)
- An Object-mode WorkSpaceTool "Draw Solid" in the toolbar, with a shape option (Box, Cylinder) in the tool header.
- Interaction: hover → the target plane is the face under the mouse (ray_cast on part meshes → face plane from the
  hit normal and point) or, over empty space, the plane through the 3D cursor with its rotation. LMB drag draws the
  base rectangle/circle; release; moving the mouse sets the height along the plane normal; click confirms; Esc/RMB
  cancels. Blender snapping settings respected where feasible (at least grid increments with Ctrl).
- Boolean by direction: on a part's face, height outward = union into that part, inward = cut from that part.
  Over empty space = new part. The result is one feature in the target part's script with a **fixed placement**
  (Location in part-local millimetres: world → object local via the inverse matrix, then / unit factor of ADR 0003).
- Afterwards the redo panel shows exact dimensions, the placement numbers and the boolean mode (New/Union/Cut).
- Draw preview during the modal: `gpu` wireframe/ghost of the solid being drawn (no worker calls during the drag).
- Precise typed input during the modal is optional for 1.5 (the redo panel covers exact values).

## 4. Tool 3 — booleans between parts with live cutters
- Stable part identity: a UUID string property per part object (`bs_part_id`), created with the part, regenerated for
  Shift+D copies (independent parts), shared by linked duplicates (Alt+D same mesh = same part).
- Operator(s) Union / Difference / Intersect: selected parts (cutters) applied to the active part (target);
  shortcuts Ctrl+Numpad +/−/* in Object Mode (Bool Tool convention), also in a BlendSolid menu. Writes a feature
  `add(ref("<cutter part id>"), mode=Mode.SUBTRACT)  # feature: bool_1` (or the equivalent that works in build123d
  0.13) into the target's canonical script. The cutter becomes wire display (and not renderable), stays movable.
- Worker side: `ref(id)` resolves to the cutter part's result **in the target's local frame** (relative transform =
  target.matrix_world⁻¹ @ cutter.matrix_world, with the ADR 0003 unit factor applied to translation). The run request
  for a target carries its dependencies (sources, tags, relative transforms, recursively); the worker caches built
  shapes by tag. The target's cache tag includes its dependencies' tags and relative transforms, so moving/rotating a
  cutter (G/R/S) or editing its parameters recomputes the target through the existing reconcile loop.
- Dependency cycles, missing cutters (deleted objects), untrusted dependencies → clear error on the target, no crash,
  no loop. A target is trusted only if all its dependencies are.
- Scaling a cutter: reject non-unit scale with a clear error (scale belongs in the script).

## 5. Success criterion test (automated, headless)
A Blender test that uses only the operators (no hand-written scripts): creates the milestone 1 default part and a
bracket with 3 holes (e.g. an L bracket from two boxes via Draw Solid union + 3 cylinder cuts via Draw Solid or
cutters), checks volumes numerically, checks that each step is exactly one undo step and one script feature.
The Draw Solid modal needs a non-interactive path for tests (call execute() with the redo-panel properties).

## 6. Manual GUI test (Windows, with the maintainer, at the end)
Numbered steps for: Shift+A primitives + redo panel + gizmos; Draw Solid on grid and on a face (union and cut);
cutters moved with G updating the cut live; undo through all of it; file reopen + trust.
