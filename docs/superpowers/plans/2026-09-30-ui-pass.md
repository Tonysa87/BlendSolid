# UI pass — pie + right-click menu, Fillet/Push-Pull feedback with native gizmos: implementation plan (draft)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Draft written from the maintainer's morning session (2026-09-30), without running Blender.** Check it against
> the code as it is after the 3a work, correct it where the code disagrees, then record the decisions as ADRs.

**Goal:** commands reachable from one pie (two native levels) and a right-click menu that follows the selection;
the sidebar shows context only; the Fillet and Push/Pull tools show the real result as their only preview, with
Blender's native handle (the one its Bevel and Push/Pull tools use) and theme colours.

**Specs:** `docs/superpowers/specs/2026-09-30-pie-menus-design.md` (Decisions),
`docs/superpowers/specs/2026-09-30-fillet-feedback-design.md` (Decisions, Native gizmos for the tools).
**Research:** `docs/research/2026-09-30-pie-menus-and-command-access.md`,
`docs/research/2026-09-30-fillet-handle-and-preview.md`.

**When:** after the 3a work in progress is at a stable point, before the 3a usage checkpoint (maintainer's call).

## Global Constraints
- Native Blender UI only: `Menu.draw` + `layout.menu_pie()`, `wm.call_menu_pie`, `VIEW3D_MT_object_context_menu`
  entries, `bpy.types.Gizmo`s of Blender's types (`GIZMO_GT_button_2d`, `GIZMO_GT_arrow_3d`); no custom-drawn
  menus or handles.
- Colours from `context.preferences.themes[0].user_interface` (`gizmo_primary`, `gizmo_hi`, …) and the view's
  selection colours, never hardcoded.
- Every existing command stays reachable (F3 finds every operator; Shift+A and Ctrl+Numpad keep working).
- Tests with numbers; GUI checks for what only the GUI shows. Everything in English.

## Review Focus
1. The pie key: tap keeps the key's own action in Object Mode (keymap test), press-and-drag opens the pie; a
   failed `poll` passes the event on.
2. Right-click menu: each selection kind shows exactly its entries; nothing BlendSolid shows for non-parts.
3. No preview line drawn through the part: while dragging, only the part's real mesh and the handle.
4. A too-large radius: the handle in the error colour with the largest working radius, the part visibly on its
   last good result.
5. Draw Solid's grid and ticks still draw on the plane (the depth change of task 5 must not hide them).

### Task 1: pie menus (native, chained)
- `VIEW3D_MT_blendsolid_pie` (level 0, order W E S N NW NE SW SE = Add, Sketch, Edit, Draw Solid, Booleans,
  Solid from Sketch, Pattern, Part & File) and one level-1 pie per family; families without commands yet show
  greyed-out items (`layout.enabled = False` on a row), never empty slots, so positions never move.
- Level-0 items open level 1 with `wm.call_menu_pie(name=…)`; tools are activated with `wm.tool_set_by_id`.
- Tests (Blender): every pie item's operator is registered; in the contexts of the test parts each item's `poll`
  matches the table in the spec; the level-0 order is as listed.

### Task 2: the pie key
- Choose the key from Blender 5.2's default Object Mode keymap (`blender_default.py`) and HardOps' (Q, Shift+Q):
  record the candidates and the reason in the ADR. Bind `CLICK_DRAG` of that key to `blendsolid.call_pie` (an
  operator of ours with a `poll`), in the add-on keyconfig.
- GUI check first (cheap): does the level-1 pie open where the chosen item was; does a `CLICK` on the key still do
  its own action.
- Tests: keymap item present with value `CLICK_DRAG`; the key's `CLICK` item untouched.

### Task 3: right-click menu on the selection
- Entries prepended to `VIEW3D_MT_object_context_menu` by selection kind: an edge (the Fillet tool's selection, or
  the edge under the mouse) → Fillet, Chamfer, Select Tangent Chain, Copy Reference; a face → Push/Pull, Draw Solid
  Here, Sketch on Face (when 3a has it); two or more parts → Union, Difference, Intersect; a cutter → Select
  Target, Remove Boolean; then a separator and Blender's own entries.
- New small operators where needed (Select Tangent Chain, Copy Reference, Select Target), each with a test.
- Tests: for each selection kind of the test parts, the menu's BlendSolid entries are exactly the listed ones.

### Task 4: sidebar = context, toolbar = one group
- `BLENDSOLID_PT_part` keeps parameters, references/warnings, the part's booleans (with Select Cutter / eye),
  display; command buttons (New Part, Draw Solid, Edit Script, Recompute) move to the pie's Part & File.
- Draw Solid, Fillet, Push/Pull registered as one toolbar group (`group=True` on the first, the others inside).
- Tests: the panel draws without command operators except the context ones; tools still activatable by id.

### Task 5: overlays with depth
- `ops_draw._draw_segments(region, segments, width, depth=False)`: `depth=True` sets `depth_test_set("LESS_EQUAL")`
  (restore after) so hidden segments don't show; the hover and selection highlights of Fillet and Push/Pull use it;
  Draw Solid's grid, ticks and labels keep `depth=False`.
- Test: the draw calls of the Fillet overlay pass `depth=True` (a draw-list test with `_draw_segments` patched).
- GUI check: drag a fillet on a box edge from a view where the opposite edges are hidden → no lines through the
  part (the maintainer's report).

### Task 6: the real result is the only preview
- Remove `preview_lines`/`drawing.fillet_preview` from the drag's draw; keep the live script edit + `runtime.kick()`.
- While the result for the current radius is pending: selected edges in a "busy" tint. On an error: the handle in
  the error colour, the label "max N mm" from the worker's bisection (`worker/blends.py`), the header as today.
- Same for Push/Pull's drag overlay (`ops_pushpull.py` draw at line ~220): no drawn stand-in for the result.
- Tests: the drag draws no preview lines; a radius above the limit sets the handle's error state and label.

### Task 7: native handle for Fillet and Push/Pull
- Replace `arrow_lines` and the hover gizmos' hand-drawn arrows with a `GIZMO_GT_button_2d` handle built like
  Blender's generic tool handle (`view3d_gizmo_tool_generic.cc`: backdrop + help line + outline, theme Gizmo
  Primary / Highlight), placed at the selected edge's midpoint offset along the faces' bisector (Fillet) or the
  pressed face's centre along its normal (Push/Pull); pressing it starts the tool's drag.
- **Approved by the maintainer (2026-09-30):** dragging the handle out of the solid makes a fillet, into it a
  chamfer (Shapr3D, Plasticity); the C key stays as a shortcut. Test: a drag of -2 mm on the default part's edge
  writes a chamfer of length 2 (volume −2·40), +2 mm a fillet.
- Parameter arrows (`gizmos.py`): colours from the theme instead of the hardcoded blue.
- Tests: the tool's gizmo group creates one `GIZMO_GT_button_2d` per selection; its matrix is at the anchor.
  GUI check: the handle looks like Blender's own Bevel tool handle.

### Task 8: tangent chain before dragging (last)
- With an edge selected, the edges OCCT will round with it in a lighter tint (the worker knows the chain:
  `BRepFilletAPI` propagation, or a tangency walk on the part's edges).
- Test: the default part's top-front edge selects its tangent chain through the template fillet (known case,
  CLAUDE.md milestone 2 pitfalls).
